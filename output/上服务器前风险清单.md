# 上服务器前的风险清单

**前提变了**：上次体检的结论是"没有可攻破的漏洞"，但那个结论建立在**只绑 127.0.0.1、单用户、数据在你自己机器上**。现在要挂到官网给客户用，等于从"本地工具"变成"多租户公网服务"——很多原本不算问题的地方，会直接变成事故。

按"会不会出事"分三档，你挑要改的。

---

## A. 不改会出事

### A1. 所有客户共用一个身份，互相能看见彼此的课程

`user_id="default"` 是硬编码的，至少 12 处：

| 位置 | 代码 |
|---|---|
| `progress/gate.py:32` | `USER_ID = "default"` |
| `pages/review.py:185/336/380` | `where(LearningProject.user_id == "default")`、`review_card(..., "default")` |
| `pages/quiz.py:183/357` | 同上 |
| `pages/dashboard.py:101`、`pages/adapt_panel.py:142` | 同上 |
| `pages/path_generator.py:370/531` | `user_id="default"` |

**后果**：客户 A 打开「间隔复习」，下拉里排的是**所有人的**学习项目；点进去看到的是别人的笔记、复习卡、测验记录。这不是"权限没做"，是"完全没有用户这个概念"。

**改法**：把 `USER_ID` 从一个常量换成"当前登录用户"，从登录态一路传下去。听着简单，但所有 `where user_id == "default"` 都要跟着改，且要有登录才能有"当前用户"——这两件事是绑在一起的。

### A2. 没有登录，而且客户能直接看到你的 API Key

- `custom_app.py:186` `demo.queue().launch(...)` 全程没有 `auth=`
- `pages/quick_setup.py:234` 模型配置页的 key 输入框 `value=current["api_key"]` —— **明文回显**

**后果**：拿到网址的人都能用（用你的 key）；更糟的是打开「模型配置」页就能把你的 DeepSeek key 复制走，自己去刷。

**改法**：加 auth（Gradio 自带 `auth=` 或 nginx basic auth）；对客户隐藏「模型配置」页，或改成只读的"由平台统一提供"。

### A3. 动手学 Agent 能操作服务器

`agent/tools.py:67` 的 `_ps()` 把命令直接交给 powershell，`safety.py` 只是一张正则黑名单。上次说过黑名单可绕过，但在你本机上"最坏是自己删自己的文件"；上了服务器，最坏是**客户删服务器文件、读 `.env` 里的 key、扫内网**。

**现在它是关着的**（`pages/coach.py` 里 `COMING_SOON = True`，事件不注册）。但这是**一个常量**——哪天你需要改回 False 试功能，忘了改回来，就是灾难。

**建议**：加环境变量硬开关，`LE_ALLOW_LOCAL_AGENT` 不为 1 时连工具模块都不加载，别只靠一个 `True/False`。

### A4. 并发是 1：第二个人点任何按钮都在排队

两处叠加：

- `custom_app.py:186` `demo.queue()` 没传参数 → Gradio 的 `default_concurrency_limit` **默认就是 1**，所有用户共享同一个事件队列
- `llm/client.py:27` `BoundedSemaphore(1)` → LLM 调用全局串行

**后果**：客户 A 在建学习路线（一条路线几十次 LLM 调用，每节 8000 字，几分钟到十几分钟），客户 B 点「开始复习」要**等 A 全部跑完**才轮到他。10 个人同时用，基本等于不能用。

**改法**：`queue(default_concurrency_limit=4)` 起步；LLM 信号量放到 3–5（配合 API 的限流）；备课队列 worker 从 2 降到 1，给用户交互让路。

## B. 上线前建议处理

### B1. SQLite 单文件，并发写会锁

数据库是 `kotaemon/ktem_app_data/user_data/sql.db`（现在 2.6MB）。多线程同时写会抛 `database is locked`，而项目里有 121 处 `except Exception`，大概率被吞成"点了没反应"。

**改法**：先开 WAL 模式（一行 pragma，能撑住小规模）；真要上量就换 Postgres——SQLModel 换连接串即可，但要跑一次迁移。

### B2. 备课队列在内存里，重启就全丢

`progress/prep.py` 的 `_Q = queue.Queue()` 和 `_STATE` 都是内存结构。**发一次新版本、重启一次进程，所有"正在生成"的课程就卡住不动了**，用户看到"准备中"永远转圈。

**改法**：任务状态落库（一张 job 表），启动时把 pending 重新入队。

### B3. 异常原文直接甩给用户

11 处 `f"❌ {e}"`（`study_workbench.py:1383/1401/1456/1609` 等）。公网上这些会泄露文件路径、库名、SQL 片段。项目里已经有 `friendly_error()`，把它们统一换掉就行。

### B4. 反向代理没配 root_path

`launch()` 没有 `root_path=`。如果你打算挂在 `https://官网.com/learn` 这种子路径下，静态资源和 websocket 会 404/连不上；要用独立域名或根路径就没事。

**改法**：`launch(root_path="/learn")` + nginx 转发 `Upgrade`/`Connection` 头。

### B5. 数据得落在持久卷上

SQLite 和上传的文件都在 `ktem_app_data/` 下面。容器化部署时**必须挂 volume**，否则重启=清库。

## C. 上线后再优化

| 项 | 说明 |
|---|---|
| 成本没有上限 | 一条路线 ≈ 40+ 次 LLM 调用、每节 8000 字。一个客户建两条路线，几十万字。建议先做"每账号每天 N 次生成"的配额 |
| 没有限流 | 接口可被脚本直接 POST（我测试时就绕过 UI 直接调过后端函数），无鉴权时等于白送 |
| 没有日志追踪 | 出了问题不知道是哪个客户、哪次调用、什么参数。至少要记 user + 动作 + 耗时 |
| 备份 | sql.db 是唯一数据源，建议每天定时 copy 到对象存储 |

---

## D. 两条路线，成本差一个量级

**路线一：内测（10 人以内的客户）**
```
加一个登录（Gradio auth 或 nginx basic auth）
→ 每个账号一个 user_id，替换掉所有 "default"
→ 隐藏「模型配置」页
→ queue 并发调到 4
→ 环境变量硬关动手学
→ 开 WAL + 挂持久卷
```
这个量级 **1–2 天**能做完，够 10 个人稳定用。

**路线二：公开官网（任何人注册都能用）**
需要真正的多租户：用户表 + 注册登录 + 数据隔离 + 配额计费 + 任务队列（Redis/Celery）+ Postgres + 资源限制。**这不是改几个文件，是按新项目重做一遍后端**。

---

## 我的建议

先在**路线一**上跑通，用真实客户验证"课程生成质量"和"学习闭环"到底成不成立——这比现在就投入多租户架构划算得多。等技术方案被验证了，再决定要不要为规模化重写。

如果同意，我可以先做路线一里最要紧的三件：**加登录 + 把 user_id 从常量变成会话变量 + 隐藏模型配置页**（A1/A2），这三件不做，内测第一天就会出隐私事故。
