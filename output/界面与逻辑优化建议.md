> **实施进度（2026-10-24 更新）**

> - ✅ **P0-2 学完自动生成复习卡**：`_set_status(已掌握)` 现在会把这一节丢进后台生成 5 张卡片（已有卡则跳过）
> - ✅ 顺带：管理面板改为浮层（不再把正文顶下去）；窄屏 900px 下工具条 152px（原 234px）
> - ⬜ 其余条目仍待做
>
> 审查范围：11 个一级页面 + 核心链路（路线 → 备课 → 阅读 → 笔记/批注 → 复习 → 测验 → 看板）
> 审查方式：真实页面截图（1440×900）+ 代码走查 + 运行时量化（首屏位置、按钮密度、轮询请求数）

## 一、总体判断

骨架是对的：**建路线 → 自动备课 → 阅读 → 记录 → 复习 → 测验 → 看数据**，这条链路在同价位产品里算完整。

问题集中在两点：

1. **每一页都在为"功能齐全"付界面代价** —— 控件抢走了内容的位置。最典型的是工作台：视口 804px，正文起点在 **866px**，也就是说进页面时**一个字都看不到**，先看到的是两个下拉框、一段进度文字和一个折叠面板。
2. **闭环有三处断了** —— 学完不产生复习卡、学习时长从来没有被记录、笔记不自动保存。所以「复习」「看板」两个页面长期是 0，用户会以为功能坏了。

下面按「页面」和「逻辑」分开说，每条都标了优先级和我建议的改法。

## 二、页面层

### P0｜工作台：把首屏还给正文

![工作台](_shots/03-workbench.png)

现状（实测）：

- 正文容器 `top = 866px`，视口只有 804px → **首屏正文 0 可见**
- 一屏内 39 个可见按钮、5 个输入框
- 「当前学习」卡片占掉 300+px：项目下拉、课程下拉、进度文字、右上角一个来源不明的 `<` 按钮、"项目与课程管理"折叠面板

建议：

- 把「当前学习」压成**一条 44px 的工具条**：`项目 › 课程` 面包屑 + 细进度条（1/29）+ 右侧「换课」图标。下拉框改成面包屑点击后弹出的浮层，不常驻。
- 进度数字（"已掌握 1 · 学习中 0 · 待学 28"）移到看板，工作台只留一条 3px 进度条。
- 「项目与课程管理」「重新载入当前课程」这类低频操作收进标题右侧的 `⋯` 菜单。
- 目录（本节目录）改成**吸顶窄栏**，滚动时高亮当前小节；现在它和正文之间还插了个孤零零的 `<` 折叠钮，视觉上像误放的。
- 目标：正文起点从 866px 降到 **< 280px**，首屏能看到标题 + 3~4 段正文。

> 参考：Readwise Reader（正文优先，工具条一行）、Notion（面包屑 + 内容全宽）。

### P0｜动手学：现在是一个空白页

![动手学](_shots/07-coach.png)

页面除了居中的输入框什么都没有：没有标题、没有说明、没有示例、没有"它能做什么/需要什么权限"。用户第一次点进来只会以为加载失败。

建议的空状态（一屏讲清楚）：

- 标题：「动手学 · 我接管你的电脑，一步步带你做」
- 一行说明：「你负责看，我负责点。每一步操作我都会先问你。」
- 3 个示例指令做成一排可点的胶囊：
  - 「帮我把这个 Python 环境配好」
  - 「打开 VS Code，建一个文件，写个 hello world 跑通」
  - 「我刚才那个报错，你看着屏幕帮我修」
- 底部一行小字：权限说明（会读取屏幕 / 会点击 / 随时可停）+「上次会话」入口
- 发送按钮旁加「停止」——现在跑起来之后没有明显的急停入口

> 参考：Cursor 的 Agent 首屏、Claude 的 computer-use 说明页。

### P1｜学习路线：一屏塞了"历史 + 新建"，还留着上个版本的手动输入

![学习路线](_shots/02-path.png)

现状问题：

- 表格里有**一整行空白行**（Dataframe 固定 3 行，只有 2 条数据）
- 表格下面还留着「项目 ID 输入框 + 打开这条路线」——上一版加的"点行直接加载"已经覆盖了这个需求，**两个入口并存**
- 标题列被压成两行还截断（"…共约…"），进度列 `1/29（3.4%` 括号被裁掉
- 「建立路线」的 4 步流程（01/04 为你定制学习路线）在首屏之外，用户看不到"这是个四步的事"

建议：

- 删掉「项目 ID + 打开这条路线」整行（点行加载保留，行尾加一个 `→` 暗示可点）
- 表格 `row_count` 跟随数据（`(0,"dynamic")`，无数据时显示空态而不是空行）；进度列换成细进度条，标题列限 2 行加省略号
- 历史区默认折叠成一行摘要（"已有 2 条路线，最近：AI 产品经理 · 1/29"），点击才展开——把首屏让给新建流程
- 新建做成 4 步 stepper，步骤条吸顶，当前步高亮

### P1｜间隔复习：0 张卡时，界面还在热情地让你"开始/评分"

![间隔复习](_shots/04-review.png)

现状：待复习 0 / 卡片总数 0，但「开始 / 下一张 →」是巨大的主按钮，四个评分按钮（重来/困难/良好/简单）都在，"显示答案"也在。用户点下去没有任何反馈。

建议：

- 无卡片时：主按钮降级为「生成第一批卡片」，评分按钮整排 `visible=False`
- 空态换成引导卡：**「你已掌握 1 节。要不要我把它变成 5 张复习卡？」**（直接调 `generate_cards_from_node`，不用跳去折叠面板）
- 有卡片时再显示评分区，且评分按钮加键盘快捷键提示（1/2/3/4）——这是 Anki 用户的核心肌肉记忆

### P1｜查漏测验：设置栏和答题区抢主次

![查漏测验](_shots/05-quiz.png)

现状：左栏"测验设置"里塞了项目、更新列表、题目数量滑杆、题型下拉、开始按钮；右栏是空的题目区和禁用态提交按钮。

建议：

- 「更新项目列表」不该出现在主流程里（维护操作），收进下拉框底部的"刷新"小项
- 「开始测验 →」移到右栏空态里作为唯一主按钮（"选好范围后，从右边开始"），左栏只保留设置
- 题目数量滑杆改成 5/10/20 三个分段按钮（滑杆选 5 个题的比例感很差）
- 提交后要有"这题对/错 → 下一题"的连续节奏，现在提交和下一题是两个并排按钮，容易点错

### P1｜学习看板：三个 0 会劝退

![学习看板](_shots/06-dashboard.png)

现状：29 / 1 / 0% / **0 分钟** / 0/0 —— 五项里三项是 0，"近 7 天学习（分钟）"永远是 0（见逻辑层 P0-1）。

建议：

- 0 值不要平铺：没有数据时换成一句"还没有学习记录，从这一节开始 →"（带跳转）
- 掌握度用环形图，比 `0%` 大字更有进度感
- "继续你的学习"卡片做得对，保留——但应该放在指标卡**上面**，先给动作再给数字

### P2｜全局导航与一致性

- **11 个一级入口**（学习首页/路线/工作台/复习/测验/看板/动手学/问答/资料库/配置/帮助）太多。建议收成 3 组：
  - 学习：首页、路线、工作台、复习、测验、看板
  - 助手：动手学、知识问答
  - 底部（设置区）：资料库、模型配置、帮助
- **5 个不同名字的"刷新"按钮**：刷新列表 / 刷新项目 / 更新数据 / 刷新课程 / 重新载入当前课程。统一成一个图标按钮（↻），hover 显示文字。
- 侧边栏图标风格不统一（有的描边、有的实心、线宽不一），建议统一到一套 1.5px 描边图标。
- 每页标题格式已经统一（大标题 + 一句副标题），这一点做得很好，动手学要补上。

## 三、逻辑层

### P0-1｜学习时长从来没有被记录过

`progress/service.py` 里有 `record_study_time()`，但**全项目没有任何地方调用它**（`grep` 只命中 `__init__.py` 的导出）。

结果：看板"近 7 天学习（分钟）"、每日学习时长图、热力图，永远读不到真实数据；只有 `dashboard/service.py` 里的演示数据函数会写。

建议：在 `_on_node_select` 记录"进入某节"，在前端 `visibilitychange` / 离开页面时上报分钟数（一次会话超过 30 秒才算），落到 `ProgressRecord(metric="study_minutes")`。这是**性价比最高的一处修复**，看板立刻活过来。

### P0-2｜学完不产生复习卡，复习页永远空

`_set_status(MASTERED)` 只做了两件事：改状态、后台生成下一节内容。**没有生成复习卡**。

卡片只能去复习页手动点「AI 提炼 5 张卡片」，而且一次只对单个知识点。

建议：标记已掌握时顺带 `generate_cards_from_node`（放后台队列，别阻塞），并在 toast 里说"已加入 5 张复习卡，明天见"。这一步做完，"学习 → 复习"的闭环才算闭上。

### P0-3｜笔记不自动保存

`note_input` 只有"保存总结"按钮触发。用户写了 8 行，切个 tab 或换课程，内容就没了——而且没有任何提示。

建议：`blur` 或每 5 秒 debounce 自动存草稿（存 `NodeNote` 即可，状态栏显示"已保存 · 刚刚"）。

### P1-1｜备课并发只有 2，29 节要排很久

`prep.py` 的 `_WORKERS = 2`。新建一个 29 节点的项目，全量备课是 14 轮 × 每轮几十秒，用户第一次进工作台会以为"没内容"。

建议分两级：**当前这一节优先**（立刻抢一个 worker），其余后台慢慢来；工作台顶部给一行"还有 26 节在后台准备（预计 X 分钟）"，让等待可见。

### P1-2｜25 处把 Python 异常直接甩给界面

形如 `return f"❌ {e}"`。用户会看到 `KeyError: 'xxx'` 这种。

建议：统一走 `llm/client.py` 里那套 `friendly_error()` 的思路——给人话，原始信息折叠在"详情"里。

### P1-3｜"已掌握"没有校验

三个按钮（学习中 / 已掌握 / 跳过）随时可点，没有任何核对。结果是看板上的"已掌握"不代表真的会。

建议：把"已掌握"改成"学完了"（降低心理门槛），真正的掌握由测验/复习正确率反推。或者至少加一道轻量确认：学完一节后弹一个小结输入框，"用一句话说说这节讲了什么"——这句话本身就是最好的检验，还能喂给批注/卡片。

### P2｜三套数据各走各的

`NodeNote`（整节总结）、`NodeAnnotation`（句子批注）、`Card`（复习卡）互不引用。

建议：批注加"一键变卡片"（批注天然是"我卡在哪"），卡片保留 `source_annotation_id`。这样用户记完笔记顺手就能进复习队列，不用二次生产。

## 四、值得借鉴的三个具体范式

| 产品 | 借什么 | 用在哪 |
|---|---|---|
| Duolingo | 单一主线的"今日任务"卡 | 首页现在两个并列卡片（回到课程 / 探索新方向），可以合成一张"今天：继续 1.1 节 → 顺便复习 3 张卡" |
| Readwise Reader | 阅读器正文优先 + 右侧批注栏 | 工作台把目录/批注挪到右侧窄栏，正文占主视觉 |
| Anki | 学完即入队 + 键盘评分 | 复习页去掉鼠标路径，1/2/3/4 直接评分 |

## 五、如果只做三件事

1. **工作台首屏重排**（正文从 866px 提到 300px 以内）—— 用户每天面对的就是这一页，收益最大，改动主要在 CSS + 布局。
2. **接通学习时长 + 已掌握自动生成卡片** —— 两处函数调用，闭环立刻活，看板和复习页不再是 0。
3. **动手学空状态** —— 纯展示层，半小时的事，但能把一个"看起来坏掉"的页面变成有说服力的入口。

后续再做：笔记自动保存、路线页删冗余入口、测验/复习的空态与键盘操作、导航收敛。
