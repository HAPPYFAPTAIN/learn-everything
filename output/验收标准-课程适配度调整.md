# 「课程适配度调整」验收标准

> 定于 2026-10-24，动手前写死。改完后逐条实测，符合标 ✅，不符合标 ❌ 并说明差距。

## 一、范围与边界（改什么、不改什么）

| # | 标准 | 检验方法 |
|---|---|---|
| A1 | **前段零改动**：起点之前的节点，`id / code / title / status / mastery / description / stage / est_hours / difficulty` 全部不变 | 调整前后各导一份节点快照，逐字段 diff，差异必须为空 |
| A2 | **前段学习数据保留**：前段节点的笔记数、批注数、复习卡数、测验记录，调整前后完全一致 | 按 node_id 统计四张表，前后比对 |
| A3 | **后段编号连续**：新后段 `code` 从起点续接、单调递增、无重复无跳号；`prerequisites` 只能指向存在的 code | 代码断言 + SQL 检查 |
| A4 | **后段可增删**：允许新增 / 合并 / 删除后段节点，数量变化不设限 | 构造一次"压减"的调整，确认节点数变少且合法 |
| A5 | **未变节点不重生成**：后段中 code 与标题都没变的节点，`description` 保持原值，不进备课队列 | 对比调整前后 description；查备课队列日志 |

## 二、诊断质量（不能编、不能空）

| # | 标准 | 检验方法 |
|---|---|---|
| B1 | **四类信号齐备**：进度（已学/总数、速度）、复习牢固度（困难次数、平均 stability）、测验正确率、参与度（笔记/批注数）四项都要出现在诊断里 | 检查诊断文本 / JSON 是否含四个维度 |
| B2 | **数据不足要明说**：已学 < 2 节或测验 0 次时，诊断必须明确写"样本不足，判断仅供粗略参考"，不得给出精确分数 | 用数据稀疏的项目跑一次 |
| B3 | **引用真实数字**：诊断里出现的每个数字必须能在库里对上（如"已掌握 2 节""12 天"） | 人工抽查 3 个数字 |

## 三、交互与确认（不能点一下就动数据）

| # | 标准 | 检验方法 |
|---|---|---|
| C1 | **先诊断、后执行**：点按钮第一次只出诊断与差异预览，不动数据库 | 点击后查节点数未变 |
| C2 | **差异可见**：明确显示"后段 旧 N 节 → 新 M 节（新增 x / 删除 y / 保留 z）" | 页面文案存在且数字自洽 |
| C3 | **二次确认才执行**：必须再点「确认调整」才改库 | 只点第一次，库不变 |
| C4 | **补充意见生效**：用户在输入框写的需求会进入调整指令 | 对比"无意见/有意见"两次生成结果不同，或日志里能看到该指令 |
| C5 | **后段有数据要拦**：后段若已有笔记/卡片，必须先警告"将删除 N 条"，未确认不执行 | 构造后段带数据的情况验证 |

## 四、可回退

| # | 标准 | 检验方法 |
|---|---|---|
| D1 | **调整前留快照**：执行前把旧路线写入项目快照 | 库中能查到快照记录 |
| D2 | **一键撤销**：撤销后节点数、code、title、status 与调整前完全一致 | 调整→撤销→再 diff，差异为空 |

## 五、入口整合

| # | 标准 | 检验方法 |
|---|---|---|
| E1 | 「批量审计旧路线」入口移除，不再出现在页面 | DOM 查询无 "批量审计" |
| E2 | 「调整路线与重新规划」折叠移除，被新面板取代 | 同上 |
| E3 | 「重新生成路线」独立保留且可用（作用于未保存预览，不动库） | 点击后预览区更新、项目节点数不变 |
| E4 | 新面板名称为「课程适配度调整」，位于学习路线页 | DOM 查询 |

## 六、真实学习时长（速度不再靠猜）

| # | 标准 | 检验方法 |
|---|---|---|
| F1 | 在工作台某节停留 ≥30 秒后切走，`le_progress` 出现 `study_minutes` 记录 | SQL 查询该表 |
| F2 | 看板「近 7 天学习（分钟）」由 0 变为正数 | 看板页面读数 |
| F3 | 不重复计时：同一节停留多次，按次累加，不出现一次几十分钟的异常值 | 两次 30 秒停留 → 合计约 1 分钟，不溢出 |

## 七、稳定性

| # | 标准 | 检验方法 |
|---|---|---|
| G1 | 服务启动无 Traceback | 启动日志 |
| G2 | 关键路径（诊断→确认→撤销）浏览器无 console error | CDP 抓取 |
| G3 | 单次诊断的模型调用 ≤1 次，且界面有"正在分析"的等待提示 | 网络请求计数 + 页面文案 |

---

**判定规则**：A1–A5、C1–C3、D2、E1–E4 为必过项（不过就算没完成）；其余为应该过，未过要写清原因。

4. 测试过程删掉了项目 1 后段的 1 张复习卡（原本 6 张，现 5 张），无法恢复。

# 位置调整（2026-10-24 15:20）

「课程适配度调整」从**学习路线页**搬到**学习工作台**，改成弹窗：

- 入口：工作台 →「管理」抽屉 → 「刷新项目 / 刷新课程」下面
- 点开后是居中的中号窗口（840×650，遮罩模糊背景），内容与原来完全一致
- 右上角「关闭」；打开时项目默认跟随工作台当前项目
- 调整完成会同步刷新工作台的进度与课程下拉
- 学习路线页只保留「重新生成整条路线」，不再有适配面板

**回归验证**：
| 项 | 结果 |
|---|---|
| 工作台入口在刷新按钮下方 | ✅ `y=235` vs 刷新按钮 `y=179` |
| 弹窗默认隐藏 | ✅ `display:none` |
| 点开显示、尺寸 | ✅ `display:flex`，840×650 |
| 点「关闭」收起 | ✅ 回到 `display:none` |
| 路线页无适配面板 | ✅ 页面文本检索无"课程适配度调整"，仍有"重新生成整条路线" |
| 启动无异常 | ✅ 无 Traceback |

**踩坑记录**：弹窗外层如果写 `display:flex!important`，会把 Gradio 的 `visible=False`（display:none）顶掉，导致「关闭」失效。改成外层只管遮罩定位、内层 `.le-adapt-center` 负责居中，显隐交回 Gradio 控制。
