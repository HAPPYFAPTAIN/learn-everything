# 验收标准：学习闭环门控（强制复习 / 强制测验）

> 设计依据：费曼学习法——讲不出来就是没学会。因此「已掌握」不再是一个按钮，
> 而是一道关卡；「复习」「测验」不再靠自觉，由系统在学习节奏里主动推。
>
> 动手前写死标准，改完逐条实测，不通过不算完成。

## A. 第一关：学完一节当场过关（硬门）

| # | 验收项 | 判定方式 |
|---|---|---|
| A1 | 点「已掌握」时，只校验速测与复述两关；**不再有停留时长要求** | 停留 0 分钟但速测 2/3 + 复述通过 → 直接落「已掌握」 |
| A2 | 阅读时长仍然统计，只作参考数据，不参与过关判定 | 心跳 2 次共 60 秒 → `le_gate.dwell_seconds` 增加约 60，误差 ≤ 5 秒；该值多少都不影响 A1 |
| A3 | 本节速测 3 题（2 选择 + 1 填空），答对 ≥ 2 题才算过 | 答对 2/3 → 通过；答对 1/3 → 不通过且提示"再测一次" |
| A4 | 复述不限字数，只要不是空的就交 AI 判；AI 判定「讲清了核心」才算过 | 空文本直接拦；胡写（如"aaaa"）判定不通过并给出具体缺什么 |
| A5 | 两关全部通过后，再点「已掌握」才真正落状态，并自动生成复习卡 | status=mastered；`le_card` 增加本节卡片 |
| A6 | 未过关时界面不撒谎：按钮文案不变，但点击后展开「过关检查」并逐条标 ✅/❌ | 面板可见；两关各自的 ✅/❌ 与数据库一致 |
| A7 | 「跳过本节」保持零门槛，不生成复习卡、不产生过关记录 | status=skipped；`le_gate` 无该节记录 |

## B. 第二关：学完 24 小时内必须复习（强提醒 + 一次确认）

| # | 验收项 | 判定方式 |
|---|---|---|
| B1 | 工作台顶部常驻节奏条，显示：到期卡数、最近到期时间、今天学习分钟 | 切课程后数值与 `le_card` / `le_progress` 一致 |
| B2 | 有到期卡且已欠 > 24 小时，节奏条变警示态，文案明确"先复习再往下学" | 构造一条 next_review 为 2 天前的卡 → 条变警示色 |
| B3 | 警示态下切换到另一节，加载不被阻断（正文照常出），但顶部给出确认提示 | 切换后正文段落数 > 0，且提示存在 |
| B4 | 点「我先学，回头补」后，当天不再提示；次日重新提示 | 记录 `gate_snooze=YYYY-MM-DD`；同日再切不提示 |
| B5 | 无到期卡时，节奏条不吓人，显示"暂无到期，专心学" | 删空到期卡 → 文案切换 |

## C. 第三关：阶段性查漏（提醒 + 一键跳转）

| # | 验收项 | 判定方式 |
|---|---|---|
| C1 | 已掌握节数为 5 的整数倍（且 > 0）时，节奏条提示做一次查漏测验 | 构造 5 节 mastered → 出现提示 |
| C2 | 点「去查漏」能跳到查漏测验页 | 点击后 `#learning-quiz-tab` 成为选中态 |
| C3 | 点「去复习」能跳到间隔复习页 | 点击后 `#learning-review-tab` 成为选中态 |
| C4 | 非 5 倍数时不出现查漏提示 | 4 节 mastered → 无提示 |

## D. 数据与安全

| # | 验收项 | 判定方式 |
|---|---|---|
| D1 | 新表 `le_gate` 自动创建，老库升级无需手工迁移 | 启动后 `PRAGMA table_info(le_gate)` 有全部字段 |
| D2 | 已有学习数据不受影响 | 改动前后 `le_knode` 状态分布、`le_card` 数量一致 |
| D3 | 门控任何一步异常都不得让整页崩 | 断网/模型失败时，速测与复述给出中文提示，仍可点「跳过本节」 |

## E. 回归

| # | 验收项 | 判定方式 |
|---|---|---|
| E1 | 工作台正文、笔记、批注、标签切换、管理面板均正常 | 逐个点击，控制台无 JS 异常 |
| E2 | 复习页、测验页、看板打开正常 | 页面有内容，无 Traceback |
| E3 | 启动日志无 Traceback | `grep -c Traceback == 0` |
| E4 | 未引入新的常驻轮询（不闪动） | 静置 10 秒，事件往返 ≤ 1 次 |

## 修掉的两个 bug

1. **批量判分会串题**：`_judge_batch` 原来靠模型返回的 `index` 匹配，模型常把 index 填成"本次待判里的第几题"，导致上一题的判定串到下一题（实测"不知道"被判对）。改成按返回顺序一一对应。
2. **填空题的下划线被 Markdown 吃掉**：`四个环节依次是 、、、。` —— 与复习页同一个病。新增 `presentation.md_safe()`，出题渲染时转义，存储不动。

# 复述区改动（2026-10-24 17:20）

用户反馈：截图里「用自己的话讲一遍」下面看不到输入框，也没有提交入口；30 字要求没必要。

**两处原因**
1. 复述用的 `gr.Textbox(show_label=False)` 在窄窗口里被压成一条缝，看起来像没有输入框
2. 弹窗内容一屏放不下，复述区整个落在滚动区外

**改法**
- 复述框加标题「你的复述」，高度固定 96px，不再用无标签样式
- 拆成两步：先做速测，**速测通过后才显示复述区**；速测区同时收起，只留结果和「重新测一次」
- 去掉 30 字下限，空着才打回，内容交给助教判

**实测**（1080×720 窗口）
| 状态 | 结果 |
|---|---|
| 速测未做（1.4） | 复述区 `display:none`，三个答题框 + 提交按钮一屏可见，不裁切 |
| 速测已过（1.3） | 速测区 `display:none`，复述框 96px + 提交按钮完整可见，不用滚动 |
| 20 字复述 | 不再被字数拦，返回具体点评而不是"至少 30 字" |

## 修订记录

**2026-10-24 19:30　去掉「读够时间」这道门**

原因：它测的是页面驻留，不是理解——挂机就能过、读得快的人反被拦、去查资料或做实操又不计时。
结果是系统奖励"待在页面上"，不奖励"学会"，和费曼学习法的初衷背离。

改动：
- `gate.check_gate()` 的 `passed` 不再与时长挂钩，只看速测 + 复述；`missing` 也不再提示差多少分钟
- `check_gate()` 返回值去掉 `dwell_ok` / `need_seconds`（`dwell_seconds` 保留，仅作数据）
- 删除 `gate.MIN_DWELL_SECONDS` 与 `gate.required_dwell_seconds()`
- 过关检查弹窗从三行变两行（速测 / 复述），文案改为"这两关"
- `add_dwell()` 与时长心跳保留：学习分钟仍用于节奏条「今天已学 N 分钟」，只是不再卡过关
